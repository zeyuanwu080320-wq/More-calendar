More calendar v2.0.0 — 使用说明（中文）
====================================================================

一、这是什么
--------------------------------------------------------------------
把学校邮件、通知截图或一段随手粘贴的文字，变成日历/提醒事项条目的
本地小工具。流程固定为三步：

  1. 粘贴  —— 邮件正文、截图，或直接输入纯文本
  2. 核对  —— DeepSeek 抽出候选事件，你逐条确认、修改
  3. 写入  —— 你点“写入”之后才会真正落地，绝不自动写入

图片永远不出本机：OCR 走 macOS 自带的 Vision 框架，只有文字会发给
DeepSeek。纯文本模式完全不经过 OCR。


二、安装
--------------------------------------------------------------------
1. 解压 MoreCalendar_v2.0.0_macOS.zip
2. 把 “More calendar.app” 拖进「应用程序」文件夹
3. 双击打开

首次打开若被 macOS 拦截：
  - 系统设置 > 隐私与安全性，在“安全性”区域点“仍要打开”
  - 或右键 App > 打开，再确认一次
  - 本 App 使用本地 ad-hoc 签名，未经过 Apple 公证，这是预期情况


三、第一次准备：DeepSeek API Key
--------------------------------------------------------------------
1. 点右上角钥匙图标，粘贴你自己的 DeepSeek API Key（不是校园账号密码）
2. 点“保存到 Keychain”
3. Key 只存在 macOS 钥匙串里：不写代码、不写日志、界面不回显
4. 若弹出钥匙串授权框，选“始终允许”


四、输入方式（两种，左侧顶部切换）
--------------------------------------------------------------------
4.1 邮件 / 截图
    - 粘贴 Outlook 邮件正文
    - 截图可以拖进来，或点图片区后按 ⌘V
    - 图片在本机 OCR，文字再发给 DeepSeek

4.2 纯文本
    - 直接输入或粘贴任意文字（微信通知、群里转发的通知等）
    - 此模式不做 OCR、不使用图片，图片区会被隐藏

4.3 切换与记忆
    - 两种输入各自保留内容，来回切换不会丢
    - 上次用的输入方式会被记住，下次启动自动恢复


五、写入目标（三种，底部右下角切换）
--------------------------------------------------------------------
  ┌──────────────┬────────────────────────────────────────────┐
  │ Apple 日历   │ 按事件类型写入 5 个独立日历，颜色区分      │
  │              │ 考试=红 生日=紫 截止=橙 预约=蓝 活动=绿    │
  ├──────────────┼────────────────────────────────────────────┤
  │ Apple 提醒   │ 按类型写入独立提醒事项列表；到期时间取      │
  │ 事项         │ “开始时间”，全天/生日只写日期，生日每年重复 │
  │              │ 不支持冲突检测与批量平移（提醒事项没有时间轴）│
  ├──────────────┼────────────────────────────────────────────┤
  │ Google 日历  │ 写入你在下拉框里选定的一个日历；类型用事件  │
  │              │ 颜色区分（红/紫/橙/蓝/绿）                  │
  └──────────────┴────────────────────────────────────────────┘

写入按钮的文案会随目标变化，底部提示也会说明事件会去哪里。
上次选的写入目标同样会被记住。


六、Google 日历配置（关键，首次使用必读）
--------------------------------------------------------------------
Google 日历需要 OAuth 授权，而 OAuth 客户端凭据必须由使用者自行提供。
本 App 不内置凭据，也不会把它打包进安装文件。

6.1 准备凭据文件
    1. 打开 https://console.cloud.google.com/
    2. 新建或选择一个项目
    3. 「API 和服务」→「库」→ 搜索 “Google Calendar API” → 启用
    4. 「API 和服务」→「OAuth 同意屏幕」
         - User type 选“外部(External)”
         - 填应用名与联系邮箱
         - 在“范围(Scopes)”里添加：
             https://www.googleapis.com/auth/calendar.events
             https://www.googleapis.com/auth/calendar.readonly
         - 在“测试用户(Test users)”里加入你自己的 Gmail 地址
    5. 「API 和服务」→「凭据」→「创建凭据」→「OAuth 客户端 ID」
         - 应用类型必须选 “桌面应用(Desktop app)”
         - 创建后点下载 JSON
    6. 把下载到的 JSON 重命名为 google_client_secret.json

6.2 放到指定路径（必须完全一致）
    ~/Library/Application Support/More calendar/google_client_secret.json

    在终端里可以这样放：
      mkdir -p "$HOME/Library/Application Support/More calendar"
      cp ~/Downloads/google_client_secret.json \
         "$HOME/Library/Application Support/More calendar/google_client_secret.json"

    注意：源码目录里的 02_Developer_Source/Support/google_client_secret.json
    只是版本备份，App 运行时**不会**读它。

6.3 连接
    1. 重启 App，底部切到 “Google”
    2. 点“连接 Google”，系统浏览器会打开授权页
    3. 同意后回到 App，日历下拉框会自动出现，默认选中主日历
    4. 想写别的日历，在下拉框里改；选择会被记住

6.4 分享给朋友使用
    如果朋友用你提供的凭据，必须把他/她的 Gmail 地址加入
    Google Cloud 里同一项目的「OAuth 同意屏幕 → 测试用户」名单，
    否则对方会收到 access_denied（应用未验证）。
    测试用户上限 100 人。

    另一种更干净的做法：让朋友自己按 6.1 创建一份凭据，
    各自独立，互不影响配额。

6.5 时区提醒（容易误会）
    Google 网页版按**该日历自身的时区**显示时间。
    如果你的 Google 日历时区是美东，而你输入的是香港时间 14:00，
    网页里会显示成 01:00——这是同一时刻的两种显示，不是写错了。
    修正方法：Google 日历 → 设置 → 时区，改成 (GMT+08:00)。


七、管理已写入的事件
--------------------------------------------------------------------
顶部“管理事件”（⌘⇧M）只显示本工具创建的事件，可删除、可批量平移。

  - 来自 Apple 日历 / Google 日历的事件都能在这里管理
  - 切到“提醒事项”时该入口会置灰——提醒事项不支持批量平移
  - “删除选中”只删勾选的；“清空所有”才是全删
  - 循环事件（如生日）删除时，Apple 会删未来所有发生，
    Google 会删除整条系列（不会留下“下一年又冒出来”的实例）


八、权限说明
--------------------------------------------------------------------
  - Apple 日历：需要“完整访问”。不要选“仅写入”，否则无法检测时间冲突
  - Apple 提醒事项：首次写入时按提示授权
  - Google：只需要 calendar.events + calendar.readonly，
    不申请建/删日历的全量权限


九、隐私与数据
--------------------------------------------------------------------
  - 图片只在本机内存中 OCR，不落盘、不上传
  - 只有文字会发给 DeepSeek
  - API Key 与 Google refresh token 分别存在 Keychain 的两个独立条目
  - Google client_secret 不进入安装包，只从上面 6.2 的路径读取
  - 本地日志只记计数与类型，导出前再脱敏一次，不含正文/标题/地点


十、常见问题
--------------------------------------------------------------------
Q1. 写入报“Google 目标不存在（404）：POST /calendars/…/events”
    通常是日历 ID 或应用过期。先确认 6.2 的文件是最新的、并在
    Google 云端启用了 Calendar API。若仍复现，导出日志（见 Q4）。

Q2. 授权后仍报 403 / insufficientPermissions
    你后来才补的 scope 不会自动进入已签发的令牌。
    退出 App 后执行：
      security delete-generic-password -s local.duishangque.SchoolEventInbox -a google-refresh-token
    再打开 App，重新点“连接 Google”。

Q3. 事件时间差好几个小时
    见 6.5：是 Google 日历时区设置，不是写错了。

Q4. 怎么把错误发给开发者
    App 底部点“导出最近 30 条”，或在终端执行：
      grep -E '"kind":"(google_diag|google_auth)"' \
        "$HOME/Library/Application Support/SchoolEventInbox/log.jsonl" | tail -20
    日志已脱敏，不含令牌。

Q5. 提醒事项里找不到“管理事件”
    正常。提醒事项没有时间轴，批量平移不适用。


快捷键
--------------------------------------------------------------------
  ⌘↩      解析（光标在哪个输入框都可以）
  ⌘⇧↩     写入已确认事件
  ⌘⇧M     管理事件
  ⌘R      解析（菜单等效）
